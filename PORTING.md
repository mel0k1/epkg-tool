# PORTING.md — встраивание epkg-tools в свою хобби-ОС

epkg-tools написан на **C99 freestanding** и не использует ни libc,
ни syscall'ы напрямую. Вся работа с «железом» идёт через один тонкий
порт-слой — `include/epk_port.h`. Если ваша ОС умеет открывать файлы,
выделять память и открывать TCP-сокеты — epkg у вас уже работает,
включая HTTPS.

---

## 0. Что понадобится

| Требование | Детали |
|---|---|
| Компилятор | C99, достаточно freestanding-окружения |
| Стек/heap | malloc/realloc/free (может быть простым bump/free-list) |
| Строковые функции | `memcpy memset memmove memcmp strlen strcpy strcmp strncmp strchr strrchr strstr` — любой компилятор и так требует первые четыре |
| TCP-сокеты | connect/send/recv/close, IPv4 или IPv6 |
| Энтропия | 32 бита «случайности» для TLS-нонсов (RDTSC, RTC, ADC-шум — что угодно) |
| Часы (желательно) | UNIX-время — для проверки сроков сертификатов; без него TLS 1.2 тоже работает |
| RAM | ~25 КБ статических буферов TLS + динамическая память под индекс |

## 1. Структура проекта

```
include/epk_port.h      ← ВАШ КОНТРАКТ: ~25 функций
src/
  epk_*.c,h             ядро epkg (парсеры, движок, TLS-клей) — не трогать
  epk_port_posix.c      эталонная реализация порта (Linux/macOS/BSD)
  tls/bearssl/          вендоренный BearSSL (MIT) — не трогать
tools/mkepkg.c          сборщик пакетов (нужен только на хосте)
```

## 2. Реализуйте порт-слой

Скопируйте `include/epk_port.h` и напишите `epk_port_<ваша_ос>.c`.
Минимальный список (полные сигнатуры и семантика — в заголовке):

```c
/* файлы */
epk_open/close/read/write/seek/unlink/rmdir/rename/mkdir
epk_symlink(target, linkpath)   /* опционально: можно всегда -1 */
epk_opendir/readdir/closedir
/* память */
epk_malloc/free/realloc
/* система */
epk_print        /* строка в консоль/лог          */
epk_exit         /* завершение процесса           */
epk_ticks        /* монотонные миллисекунды (0 = нет) */
epk_time         /* UNIX-секунды (0 = часы не настроены) */
epk_seed         /* 32 бита энтропии              */
epk_getenv       /* может всегда возвращать NULL  */
epk_is_dir       /* нужен только mkepkg, не epkg  */
/* сеть */
epk_tcp_connect(host, port, timeout_ms)
epk_tcp_send / epk_tcp_recv / epk_tcp_close
```

Эталон для сверки — `src/epk_port_posix.c` (~200 строк).

Замечания по реализации:

* `epk_tcp_recv` — блокирующий; рекомендуемый таймаут 30 с
  (в POSIX-бэкенде это `SO_RCVTIMEO`). Возврат: `>0` байты, `0` —
  чистое закрытие, `<0` — ошибка.
* `epk_seed()` может быть слабым (TSC, jiffies, адрес стека) — TLS
  смешивает его в HMAC_DRBG, этого достаточно для клиентских нонсов.
* Если у вашей ОС нет DNS — реализуйте `epk_tcp_connect` только для
  IP-литералов и используйте IP-адреса в `epkg.conf`.
* `epk_symlink` — единственная «опциональная» функция: если symlink'ов
  в вашей ФС нет, верните из неё всегда `-1`; epkg при политике
  `symlinks = keep` будет молча пропускать их (как при `deny`).
  Докачка (`Range`) и dep-resolver v2 не требуют ничего сверх базового
  списка: resume работает через обычные `epk_seek`/`epk_open`.

## 3. Соберите

```sh
CC=ваш-кросс-компилятор make          # см. Makefile
make CC=ваш-кросс-компилятор mkepkg   # опционально, для хоста
```

Ядро epkg не требует изменений под вашу ОС — **все** различия живут
в файле порта. TLS-профиль (BearSSL): TLS 1.2, ECDHE_RSA/ECDHE_ECDSA
с AES-128/256-GCM, кривые x25519 + P-256/384/521, RSA PKCS#1 verify,
X.509-валидация (br_x509_minimal). Если нужен другой профиль — правится
одна функция `epk_tls_connect()` в `src/epk_tls.c`.

## 4. Первая настройка в вашей ОС

1. Положите `epkg.conf` (например, в `/etc/epkg.conf`):

   ```
   mirror = https://raw.githubusercontent.com/<user>/<repo>/main
   ca     = /etc/epkg/ca.pem
   ```

2. Положите бандл корневых сертификатов (`ca/roots.pem` из поставки,
   или соберите свой из Mozilla CA store) в `/etc/epkg/ca.pem`.
   Без `ca` epkg работает, но **не проверяет** цепочку сертификатов
   (печатает предупреждение) — hostname-проверка листового сертификата
   всё равно выполняется.

3. Проверьте:

   ```
   epkg update
   epkg search hello
   epkg install hello
   ```

## 5. Интеграция в образ / QEMU-тестирование

Удобный цикл — держать «зеркало» на хосте и указать его вторым mirror:

```sh
# на хосте
python3 -m http.server 8000 -d /path/to/repo
```

```
# epkg.conf в гостевой ОС
mirror = https://raw.githubusercontent.com/<user>/<repo>/main
mirror = http://10.0.2.2:8000        # QEMU host-forward
```

Для распаковки в образ без запуска ОС используйте `root`:

```
root = /mnt/os-image/
```

или переменную `EPKG_ROOT` на хосте (POSIX-сборка epkg), или ключ CLI
`--root` — он удобнее тем, что не требует править конфиг:

```sh
epkg install --root /mnt/os-image base busybox nano
```

### Genesis: наполнение чистого образа

Полный сценарий первичной загрузки ОС пакетами (см. README.md,
«Genesis»): если при заданном `--root` каталоги БД/кеша не сконфигурированы
явно, epkg размещает их ВНУТРИ образа — `<root>/var/lib/epkg` и
`<root>/var/cache/epkg`. Тогда установленное состояние едет вместе с
образом: первая загруженная ОС сразу знает, что в ней стоит, и
`epkg upgrade` в ней работает из коробки. Обратно: задайте `db =` /
`cache =` явно, если хотите держать кеш на хосте.

```sh
# хост: наполняем чистый образ
epkg --conf genesis.conf install --root /mnt/os-image base busybox nano
epkg --conf genesis.conf list   --root /mnt/os-image
# внутри ОС после первой загрузки:
epkg upgrade
```

## 6. Ограничения по дизайну (осознанные)

* Зависимости разрешаются автоматически (v2: topo-порядок,
  версии-ограничения, циклы). При `epkg upgrade` устаревшая зависимость
  подтягивается до версии из индекса, а при обычном `epkg install`
  несовместимая версия = ошибка конфликта (`--no-deps` возвращает
  v1-поведение «только предупреждение»).
* `epkg upgrade` не умеет даунгрейд и дельты: пакет заменяется целиком
  (файлы удаляются по манифесту, затем распаковываются новые).
  Отдельной команды «downgrade» нет.
* Симлинки: `deny` (по умолчанию) — пропускать, `keep` — создавать
  (см. epkg.conf); удаление по БД работает в обоих случаях.
* TLS 1.2 only (TLS 1.3-серверы, не имеющие 1.2, не поддерживаются —
  на практике все крупные CDN поддерживают).
* Отсутствие CA-бандла = работа без проверки цепочки (громкое
  предупреждение). Для хобби-ОС это осознанный компромисс; положите
  `ca.pem` — и проверка включится сама.

## 7. Чеклист портирования

- [ ] `epk_port_<os>.c`: все 24 базовые функции (+ опциональный `epk_symlink`)
- [ ] `make` проходит вашим компилятором
- [ ] `epkg version` печатает версию
- [ ] `epkg update` качает index.json (сначала `http://`, потом TLS)
- [ ] `epkg install hello` распаковывает в `root`
- [ ] файлы появляются в вашей ФС, `epkg list`/`remove` работают
- [ ] `epkg install <pkg-с-зависимостями>` ставит зависимости первыми
- [ ] `epkg upgrade` обновляет устаревший пакет из world (и его зависимости)
- [ ] `epkg install --root /mnt/img ...` кладёт файлы и БД внутрь образа
- [ ] обрыв связи во время скачивания → повторный запуск докачивает
      (в кеше остаётся `<файл>.part`)
- [ ] TLS: с `ca = ...` — «certificate chain verified» (ошибок нет)
